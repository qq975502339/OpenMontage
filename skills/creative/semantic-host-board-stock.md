# 旁白驱动的主持人—黑板—实景解说视频

## 概览

这是一套可独立执行的视频制作方法，适用于经济、商业、产业、政策、科技等主题。它把已验证的制作经验固化为可执行的镜头、动画、字幕、素材和验收契约；执行时只使用当前主题的旁白、事实、素材和用户提供的视觉资产，不依赖任何既有项目、项目目录或历史成片。

旁白是整条视频的时间主线：旁白决定主持人、黑板和实景什么时候出现。镜头顺序必须服从语义和论证关系，不能为了省事固定成“主持人→黑板→实景”的循环。

## 技能独立性与执行边界

- 不要求寻找、打开或复刻任何既有项目；本技能本身就是完整制作规范。
- 不把任何历史项目名称、主题事实、数字、日期、货币、地点、公司、字幕、黑板文字、实景素材、驱动音频或引用来源带入新视频。
- 新视频从当前主题的研究结论，以及 OpenMontage 生成或用户覆盖的旁白、字幕、黑板和主持人资产，结合本技能的视觉契约重新建立时间轴。
- 可复用的是三类全屏画面的视觉语法、语义化镜头决策、动态黑板写入、锁定数字人镜头、字幕层级、素材筛选规则和验收方法；不可复用的是任何具体内容。

## OpenMontage 能力边界（硬规则）

- 视频的研究整理、脚本、TTS、字幕、黑板资产、数字人、实景检索、素材下载、合成、探测和验收，必须全部通过 OpenMontage pipeline、工具注册表和检查点执行。
- 禁止绕过 OpenMontage 直接调用外部 provider SDK/API、临时脚本或项目外的生成器来替代已注册工具；FFmpeg、Remotion、AutoDL、Pexels、Pixabay 等只有在项目工具注册表中被发现并通过 preflight 后才能使用。
- 如果所需能力未在工具注册表中配置，必须报告 `blocked` 并说明缺少的 provider 或权限；禁止静默换模型、换供应商、换合成路径或用假素材代替。
- 用户提供的研究资料和可选覆盖素材只能作为 OpenMontage 阶段的输入，不能绕过项目目录、artifact、asset manifest、checkpoint 和最终验收流程。

## 可执行生产协议（必须按顺序执行）

### 0. 输入与输出契约

唯一必需的外部输入是当前主题的研究资料，至少包含可核验事实、来源、主题范围和需要解释的核心问题。标题、时长、画幅、旁白稿、旁白音频、时间码字幕、黑板底图、主持人占位图/参考图、实景素材和 provider 配置都属于 OpenMontage 的项目能力：只能由 research、proposal、script、assets、audio、subtitles 和 compose 阶段，通过已注册工具自动生成、解析或取得。用户可以提供这些内容作为覆盖项，但不能把它们列为技能使用前的必需条件。

如果研究资料没有指定标题、目标时长或画幅，由 proposal 阶段依据主题范围和项目默认值决定并写入 `decision_log`；这类缺省值不是阻断条件。

只有研究资料缺少可核验事实、主题范围无法确定，或经过 preflight 后确实没有任何获批的生成/检索工具时，才将状态标记为 `blocked`。禁止用旧项目内容、临时文案、假素材或无声片段替代缺失能力。

必需输出：`project.json`、`artifacts/script.json`、`artifacts/scene_plan.json`、`artifacts/asset_manifest.json`、`artifacts/edit_decisions.json`、`artifacts/props.json`、`artifacts/subtitles.srt`、`artifacts/render_report.json`、`artifacts/final_review.json` 和最终视频。所有生成物必须写入 `projects/<project-id>/`。

### 1. 初始化与前置检查

1. 使用 `hybrid` pipeline，创建独立的 `projects/<project-id>/` 工作区。
2. 记录 `composition_mode` 和 `render_runtime`。定制化成片推荐 `atelier`；当 Remotion 和 HyperFrames 都可用时，必须按照 OpenMontage 规则同时展示两者的优缺点并等待选择，禁止静默切换运行时。
3. 固定最终旁白音频和字幕文件后再规划镜头；禁止先渲染画面、最后再把旁白硬贴上去。
4. 为旁白建立连续 cue：`c001`、`c002`……每个 cue 只表达一个主张、动作或转折，并记录 `start`、`end`、`text`。

### 2. 配额与镜头决策

默认时长配额是：主持人 `20%`、黑板信息卡 `40%`、真实实景 `40%`。允许误差：主持人 ±3 个百分点，黑板和实景各 ±4 个百分点；超出误差必须在渲染前重新分配 cue、调整旁白节拍或重写脚本，不能渲染后用任意拖长画面掩盖。

每个主持人片段必须为 5–15 秒。配额、单段时长和语义匹配必须同时满足。镜头顺序由旁白语义决定，可以是任意组合，不得套用固定的“主持人→黑板→实景”循环：

- 主持人：提出问题、解释转折、承接段落、总结结论。
- 黑板：呈现数据、定义、比较、因果链、结构化矛盾和结论推导。
- 实景：呈现旁白正在说明的具体地点、人物、行业、消费或现实后果。

### 3. `scene_plan` 必填结构

每个场景必须填入以下字段；相邻场景必须无间隙、无重叠，并且在任意时刻只有一个全屏主画面：

```json
{
  "duration_seconds": 120,
  "quota_target": {"host": 0.20, "board": 0.40, "stock": 0.40},
  "segments": [
    {
      "id": "s001",
      "kind": "host",
      "start": 0.0,
      "end": 8.0,
      "cue_ids": ["c001"],
      "reason": "提出本段核心问题",
      "asset_id": "host_001",
      "subtitle_source": "artifacts/subtitles.srt"
    },
    {
      "id": "s002",
      "kind": "board",
      "start": 8.0,
      "end": 24.0,
      "cue_ids": ["c002", "c003"],
      "reason": "把数据关系写成因果链",
      "asset_id": "board_card_001",
      "write_start": 8.0,
      "write_complete": 22.0,
      "hold_end": 24.0,
      "layout_regions": ["title", "left_panel", "right_panel", "bottom_conclusion"],
      "subtitle_source": "artifacts/subtitles.srt"
    },
    {
      "id": "s003",
      "kind": "stock",
      "start": 24.0,
      "end": 32.0,
      "cue_ids": ["c004"],
      "reason": "展示旁白所说的现实后果",
      "asset_id": "stock_001",
      "subtitle_source": "artifacts/subtitles.srt"
    }
  ]
}
```

`kind` 只能是 `host`、`board`、`stock`。`reason` 必须说明画面为什么服务当前旁白；没有 `cue_ids` 的画面不得进入时间轴。黑板段必须有 `write_start`、`write_complete`、`hold_end`，且 `hold_end - write_complete >= 2.0`；若旁白时间不足以完成书写和停留，必须先改旁白或拆分 cue。

### 4. 三类画面的执行规则

- **主持人**：全屏展示，使用项目资产阶段解析的主持人占位图/参考图；用户提供自定义人物资产时优先使用。每个片段使用对应的完整旁白音频驱动数字人；镜头、构图、背景和人物位置锁定。最终旁白仍作为独立音频层，数字人片段不能把另一条声音烧进成片。提示词必须禁止推拉摇移、重新构图、背景变化和画面抖动，并检查脖子、喉咙、下巴、肩膀、衣物和麦克风的皮肤波动、液化、融化、拉伸和几何变形。主持人画面同样必须显示共享字幕。
- **黑板**：每段都从项目资产阶段解析的干净黑板底图开始；用户提供自定义底图时优先使用。在 `write_start` 后按照 cue 顺序逐笔显示标题、数据、横线、边框、箭头和重点。渲染前为每个元素分配不重叠的 `layout_regions`。禁止擦除、重绘、移动、静态整卡出现、旧卡闪回、内容覆盖和越界；写完后至少停留 2 秒再切走。黑板字是信息图形，不替代共享字幕。
- **实景**：只使用能直接支持当前 cue 的真实素材，全屏显示，除共享字幕外不叠加黑板卡、主持人、标题或额外面板。Pexels/Pixabay 先排除搜索结果前 10 条，再在剩余结果中按语义和画质筛选；少于 10 条时只从最后几条可用结果中选。`asset_manifest.json` 必须记录提供方、来源链接、许可证和实际选用结果的位置。
- **字幕与音频**：所有画面引用同一份最终旁白时间码；不得为不同画面手写另一套字幕。旁白不能出现在黑板图形层里，黑板图形也不能被误当成字幕。

### 5. 阻断式验收门

渲染前必须通过：输入完整性、cue 连续性、配额误差、单段时长、素材来源、黑板布局不重叠和 `scene_plan` 无间隙/无重叠检查。渲染后必须通过：`ffprobe`、全场景边界抽帧、黑板书写完成点抽帧、字幕/旁白同步、音频完整性、黑帧/闪帧扫描、旧主题残留扫描和数字人稳定性检查。

任何一项失败都只能标记为 `blocked` 或 `needs_revision`，不得标记 `pass`、不得交付最终视频。修复必须回到产生问题的阶段：时间轴错位改 `scene_plan`，旁白错位改 cue/音频，黑板覆盖改布局和书写动画，素材不符改资产检索，数字人变形改驱动片段；禁止只靠剪辑层叠加或拖时长掩盖问题。

## 必须使用的制作路径

- 使用 `hybrid` pipeline。
- 这种定制化视觉优先使用 `composition_mode="atelier"`，合成运行时优先使用 `render_runtime="remotion"`。
- 每个时间区间只允许一个全屏主画面。不能把实景压在黑板上，也不能让黑板卡覆盖实景或主持人。
- 所有黑板画面都使用项目资产阶段解析的干净黑板底图；用户提供自定义底图时优先使用。
- 旁白、字幕、黑板书写和主持人动作必须保持为独立层。

## 语义化镜头规划

先完成旁白，再锁定画面。把旁白拆成“一个主张或一个信息动作一个节拍”，然后按功能选择画面：

| 旁白功能 | 优先画面 |
|---|---|
| 开场问题、解释、转折、总结 | 全屏数字人主持人 |
| 数据、定义、比较、因果机制 | 黑板信息卡 |
| 具体地点、人物、行业、消费和现实后果 | 全屏真实实景 |

建立信息依赖关系，确保解释画面不会早于它所解释的旁白。场景可以是主持人→黑板→实景，也可以是实景→黑板→主持人，具体顺序由旁白决定。任何画面变化都必须有对应的旁白触发点。

每个黑板卡和实景片段都必须在 `scene_plan` 中绑定明确的旁白 cue。黑板卡至少记录 `write_start`、`write_complete` 和 `hold_end`；实景片段必须绑定它所说明的主张。没有对应旁白 cue 的画面不得进入最终时间轴。

主持人片段必须全屏展示，单段时长 5–15 秒。使用 AutoDL MiniMax H3 图像加音频工作流时，每个片段都必须使用该片段对应的完整旁白音频驱动；镜头、构图和背景保持锁定。最终成片的旁白仍作为独立音频层，不把旁白烧进数字人视频。

数字人提示词必须明确禁止推拉摇移、重新构图、背景变化和画面抖动，并要求脸部以外的区域保持稳定；重点检查脖子、喉咙、下巴、肩膀、衣物和麦克风，不得出现皮肤波动、液化、融化、拉伸或几何变形。

## 黑板信息卡规则

- 每个黑板片段都从项目资产阶段解析的干净黑板底图开始，不能在切换时短暂显示上一张卡片。
- 按照旁白介绍信息的顺序，逐步写出文字、横线、边框、箭头和重点标记。
- 渲染前必须为标题、数据、面板、注释和箭头分配互不重叠的区域。
- 禁止擦除、重绘、移动或覆盖已经写出的内容，禁止新内容压住旧内容。
- 在切走前必须完成本段旁白所需的书写，完成后默认停留约 2 秒；如果旁白需要更长停留，应以旁白为准。
- 黑板字是信息内容，不是旁白字幕。旁白字幕使用独立安全区，不能把整段旁白直接写到黑板上。

## 实景素材和字幕

只在实景能直接支持具体论点时使用 Pexels 或 Pixabay 的真实视频。执行项目约定：先排除搜索结果前 10 个，再从剩余结果中选择；如果结果少于 10 个，就使用最后几个可用结果。把提供方、来源链接和许可信息写入 `asset_manifest.json`。

实景片段必须全屏显示，只允许保留字幕，不叠加黑板卡、主持人、标题或额外信息面板。

字幕必须从同一份带时间码的最终旁白生成，并且在主持人、黑板和实景三类画面中都保持同步可见。黑板书写不能被误当成字幕。

## 哪些可以复用，哪些必须重做

可以复用：合成逻辑、三类画面的视觉语法、黑板区域规划、颜色和运动语言、用户提供的主持人视觉身份、锁定镜头提示词、字幕样式、实景筛选规则、项目产物结构和自检清单。

每个新主题必须重新生成或重新验证：研究结论、论证结构、脚本、旁白、时间码、黑板文字和数据、实景搜索词与视频、数字人驱动片段、引用来源、标题和元数据。

“只替换旁白”不是有效的改编方案。新旁白必须重新检查它对应的黑板信息、实景内容、数字人口型和时间轴。

## 质量门槛

渲染前先运行项目的产物和素材路径验证。渲染后必须完成：

1. 使用 `ffprobe` 检查视频流、音频流、分辨率、帧率、时长和文件大小。
2. 在每个场景边界、每张黑板卡书写完成处和每次主持人重新出现处抽帧检查。
3. 检查是否有闪帧、黑帧、错误场景、素材缺失、文字覆盖、黑板未写完就切走等问题。
4. 对照时间码检查字幕和旁白，确认旁白清晰、没有静音和削波。
5. 扫描所有可见文字和旁白，确认没有残留旧主题名称、日期、货币、地点、统计数据、引用或旧实景。
6. 将结果写入 `render_report.json` 和 `final_review.json`，未完成自检的成片不能标记为最终交付。

## 硬性验收标准

以下条件全部满足才允许标记为 `pass`：

- **时间轴对应率 100%**：每个场景、每张黑板卡和每段实景都有旁白 cue；不存在“旁白已经讲到下一点但画面还停在上一点”的情况。
- **黑板动态率 100%**：所有黑板卡都从干净底图开始，文字和图形逐步写出；不能一开始静态出现，也不能在黑板尚未写完时切走。
- **黑板停留合格**：每张卡完成书写后至少保留约 2 秒，除非旁白明确要求更长；不能出现刚写完就切走。
- **覆盖与擦除为零**：不允许旧卡残留、擦除时重新闪回旧内容、文字互相覆盖或面板越界。
- **边界闪现为零**：每个场景边界前后抽帧检查，不能出现错误画面、黑帧、空白帧或一瞬间跳回上一场景。
- **字幕覆盖率 100%**：主持人、黑板和实景画面中的字幕都来自最终旁白时间码，并且可读、无明显错位；黑板文字不替代字幕。
- **数字人镜头稳定**：主持人片段无镜头移动、重构图、背景漂移、脖子或喉咙皮肤变形；每段时长保持在 5–15 秒。
- **实景层级正确**：实景为独立全屏画面，除字幕外没有黑板卡、主持人或额外信息面板。
- **音视频完整**：存在视频流和音频流，旁白完整可听，无静音、削波和明显口型错位；`ffprobe` 检查通过。
- **主题残留为零**：旧主题的名称、数据、日期、货币、地点、引用、字幕和素材不得残留。

## 常见错误及修正

| 常见错误 | 修正方式 |
|---|---|
| 镜头固定循环 | 重新建立旁白节拍和信息依赖关系，让语义决定顺序。 |
| 实景切回黑板后文字静态出现 | 从干净黑板开始，按照当前旁白重新执行逐步书写。 |
| 黑板文字互相覆盖 | 预先规划不重叠区域，移除擦除流程，重新渲染独立黑板片段。 |
| 数字人嘴型与旁白不匹配 | 使用该主持片段对应的完整旁白重新生成 H3 片段。 |
| 实景遮挡黑板或带有额外信息卡 | 把实景设为独立全屏画面，只保留字幕。 |
| 换了旁白却保留旧数据 | 重新生成脚本、黑板数据、实景搜索、引用和元数据，并执行残留内容扫描。 |
| 为赶进度跳过自检 | 可以批量执行检查，但每条视频仍必须完成文件探测、边界抽帧、字幕音频检查和最终复核。 |
