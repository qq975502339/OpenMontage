# Structure Patterns

## Seven-Part Explainer Spine

1. Hook: present a contradiction, surprising implication, or familiar pain point.
2. Problem reframe: show why the obvious explanation is incomplete.
3. Concept split: define only the terms needed to understand the mechanism.
4. Hidden variable: name the one primary variable that unlocks the story.
5. Mechanism chain: show how the variable changes incentives and behavior.
6. Evidence checkpoint: provide data, cases, or observable signs. Separate proof from illustration.
7. Conclusion reversal: return to the opening and make it feel newly obvious.

## Mechanism Chain Templates

### Incentive Distortion

Metric changes -> actors optimize for the metric -> behavior drifts from original purpose -> public outcome worsens -> reform creates a new metric.

### Balance Sheet Pressure

Cash-flow pressure -> risk tolerance changes -> short-term decisions dominate -> long-term capability weakens -> system becomes fragile.

### Visibility Pressure

More visibility -> higher reputational risk -> safer behavior -> less authentic information -> weaker trust.

### Feedback Loop

Initial advantage -> more attention/capital/data -> better performance -> more advantage -> market concentration.

### Trust Substitution

Low trust -> more rules and verification -> higher transaction cost -> less flexibility -> even lower trust.

## Outline Templates

### Short Script: 2-3 Minutes

```markdown
1. Hook: one scene or contradiction
2. Reframe: what people usually misunderstand
3. Hidden variable: name it plainly
4. Mechanism: 3-step chain
5. Example: one concrete case
6. Ending: one reversal sentence
```

### Standard Script: 5-8 Minutes

```markdown
1. Cold open
2. Common explanation and why it is insufficient
3. Necessary background, kept narrow
4. Hidden variable
5. Mechanism chain, step by step
6. Evidence or case comparison
7. Implications
8. Reframing close
```

### Long Article or Deep Dive

```markdown
1. Reader promise
2. Surface story
3. Deeper mechanism
4. Historical or institutional context
5. Case stack
6. Counterarguments
7. What would change the mechanism
8. Conclusion
```

## Source-Backed Structure Families

### Metric Explainer

Best for GDP, CPI, unemployment, rankings, valuations.

```markdown
1. Show the same metric producing conflicting interpretations
2. Ask which version/definition is being used
3. Teach the boundary of the metric with concrete judgment examples
4. Explain calculation methods
5. Explain comparison adjustments
6. End with the better question the audience should ask
```

### Infrastructure Power Map

Best for stablecoins, payment systems, logistics platforms, identity systems.

```markdown
1. Stack recent moves by governments and companies
2. Show why the "just hype" explanation is too small
3. Define the infrastructure layer
4. Map who gains fees, data, reserves, or control
5. Show incumbent/regulator reaction
6. End with unresolved systemic tension
```

### Institutional Process Walkthrough

Best for IPOs, admissions, licensing, procurement, audits.

```markdown
1. Enter through a concrete protagonist or event
2. Compare systems by who bears the screening burden
3. Walk through the process gates
4. Translate rules into actor incentives
5. Humanize the cost through a case/interview
6. Zoom back out to policy or system design
```

### Market Accident Reconstruction

Best for crashes, squeezes, bank runs, derivative blowups.

```markdown
1. Start with the accident and stakes
2. Rewind to the bet or imbalance
3. Explain leverage, deadline, or liquidity constraint
4. Show the forced decision point
5. Explain intervention or rule change
6. End with the design lesson
```

### Country Economy Deep Dive

Best for national economies, sanctions, resource traps, development stories.

```markdown
1. Contrast headlines with a deeper economic puzzle
2. Build only the historical context needed for the current structure
3. Identify the hidden institution, rent, or constraint
4. Map sectors and actors around that constraint
5. Add current indicators and stress points
6. End with scenario uncertainty, not a fake prediction
```

## Section-Level Rules

- Each section should answer one question and create the next.
- Do not define terms before the audience feels the need for them.
- Prefer "actor + constraint + decision" sentences.
- Use numbers as turning points, not decoration.
- If a section cannot be connected to the mechanism chain, cut or relocate it.
