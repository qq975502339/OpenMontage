# 声音

## 文案（配音之前）

- 口语、第一人称，像在跟朋友算账，不要“AI 腔”的排比和总结句。如果用户有自己的口播语料，照着他的说法写。
- 每一句都要接住上一句。写完通读一遍，看有没有哪句是凭空冒出来的。
- 插原声的地方先写一句铺垫，告诉观众接下来是谁、他会说什么性质的话：“难怪某某总爱说这句：”“连某某自己都说：”。
- 用户点头之前不做正式配音。

## 配音：先用临时语音

**第一步：临时配音**（`scripts/temp_voice.py`）。用免费的 edge-tts（默认“云希” `zh-CN-YunxiNeural`）给每句话出一条，同时生成 `timeline.json`，里面有每个字的时刻、原声插段和片名的位置。画面全部挂在这些字的时刻上（`cue(句id, '词')`），所以后面换了配音，画面会自动顺延。

**第二步：正式配音**（文案和画面都定了以后）。正式配音可以是任何 TTS、克隆音色或真人录音，每句存成 `voice/<句子id>.final.wav`，然后：

```bash
python scripts/temp_voice.py film/script.json --asr
```

它会换上正式配音、切掉静音，并用 faster-whisper 重新逐字对齐。

**所有配音都这样处理：**
- 每句先切掉首尾静音，再按 `gap` 留停顿，一般 0.35 秒，换段处 0.5 秒。不切静音的话，每句前后会带 0.2–0.6 秒空白，再加上停顿，节奏会时长时短。
- **保持原速，不要用 atempo 事后加速。** 切掉静音后再拉到 1.1 倍，听感会很急促。要说得快一点，就在生成时调语速（edge-tts 的 `rate`，或正式 TTS 自己的语速参数）。
- 逐字对齐的键用完整的句子编号。只截前几个字符当键的话，“b10b”会覆盖“b10”，字幕和卡点就全错了。

## 原声

见 `sourcing.md` 的原声一节。混音时，原声和配音放在同一条人声总线上，这样配乐会自动给它让路。原声和配音的响度差在 2dB 以内（`mix.py --check`）。

## 音效和配乐

音效只跟画面里的动作走，一个动作一声，同一时刻只留一个。实践中验证过的口味：
- 镜头沿桌面滑过去、摇去找下一个：很轻的 whoosh。
- 横推换人、画框甩进来、推近画框：电影感的快 whoosh。
- 巨字立起来、身后换背景：一声低沉的撞击。
- 累加滚数：滚的时候一条短的上升音，停在那个数上时一声电影感撞击。片名也用电影感撞击。
- 原文倒成桌面、两个世界之间的虚化过渡：低沉的 whoosh。
- 开头如果用关键词快闪：每张一声很轻的翻书。
- 资金流动的管子：很轻的 whoosh。
- **不用**：金币、收银机、筹码这类卡通化的“钱”音效；紧张的滴答配乐和放映机声，容易显得怪。

配乐用一条平稳的底乐，压在配音下面约 18dB，人声出来时 sidechain 自动压低，片名期间抬高。素材推荐从 Openverse 检索 CC0 的（`https://api.openverse.org/v1/audio/?q=…&license=cc0`），并把来源记进清单。

如果没法亲耳听（比如由 AI 代理混音）：
- 按峰值归一每个音效（`mix.py` 的 `peak` 参数），不靠猜音量；
- 混完量响度：开头、配音、每段原声都要量；
- 交付时请用户重点听原声的剪口和语速。

`scripts/mix.py` 已经实现了上面这些：配音、原声、音效、配乐，最后到 -14 LUFS。
